## 数据完整性检查

首次导入前，先保存原始目录 JSON、完整文件清单及原始源码档案。不要在调试导入器时删除原始资料。

```bash
node scripts/data/import-legacy.mjs --root /private/legacy-checkout --data-dir /private/new-data
node scripts/data/verify-baseline.mjs --data-dir /private/new-data --catalog /private/baseline-catalog.json --inventory /private/baseline-files.json
```

导入目标必须是新目录或空目录。核验命令比较完整目录字段和数组顺序，并逐条核对历史文件路径、字节数和 SHA-256；共享同一哈希的文件内容只需读取一次。不能仅凭资料包数量相同认定迁移成功。

- [x] 原方向、课程、分类、资料包与资源结构保持一致。
- [x] 全部 1,630 个历史文件路径都有持久化映射，包括页面目录中未登记的文件。
- [x] 文件内容按 SHA-256 存储，历史路径视图保留中文及空格等名称。
- [x] 生成的页面目录来自外部数据库；生产资料不重新复制进源码的 `static/files`。
- [x] 重复准备同一版本可以接续；异常文件视图拒绝发布，保留数据供维护者检查。

资料数据和发布目录建议位于同一文件系统，以硬链接共享文件内容。跨文件系统时，仅在 `EXDEV` 下回退为校验后的独立只读复制，不使用文件符号链接。按当前规模，每份跨卷 release 会额外占约 4.29 GB，清理和保留策略见[运维与迁移](./operations.md)。

## 已知外部链接例外

当前基线含两条 `example.com` 占位链接和一条历史 GitHub 附件链接。占位链接检查返回 `404`；附件首次下载返回 `416` 与 `Content-Range: bytes */0`，后续从本机和服务器重试超时，均未取得可核验内容。保留原有记录和来源信息，未构造一个替代空文件，也未将其宣称为已经备份的本地文件。

完整导出包保证包内资料可恢复，不能保证上述第三方链接未来可访问。这三条链接属于迁移前已存在的例外，应在功能比对中单独记录，不能将其算作本轮新增缺失。

## 完整导出与恢复检查

使用源码自带工具导出一致的 SQLite 快照和快照引用的全部文件，包括完整上传的待审附件及历史版本。不要复制正在写入的 SQLite 文件作为备份，不要同时手工删除哈希文件。

```bash
node scripts/data/backup.mjs export --data-dir /private/live-data --output /private/backup/kym-complete.tar.gz
node scripts/data/backup.mjs verify --archive /private/backup/kym-complete.tar.gz
node scripts/data/backup.mjs restore --archive /private/backup/kym-complete.tar.gz --data-dir /private/restored-data
```

恢复目标必须尚不存在。工具校验格式、数据库完整性、逻辑状态、文件清单和实际字节，遇到损坏、异常路径、链接或重复归档条目应拒绝安装；恢复失败不能覆盖已有运行目录。

- [x] 首轮完整资料包成功校验并恢复到新目录。
- [x] 测试确认未登记文件、待审资料和审核状态可保留。
- [x] 测试确认同时上传和发布时，导出仍对应一个一致的数据库状态。
- [x] 测试确认损坏归档及路径穿越、软链接、硬链接成员不会覆盖现有数据。
- [ ] 在最终源码已提交并可从 GitHub 获取后，重新生成记录该准确版本的完整备份。
- [ ] 在空白 Linux 环境中，仅使用该源码版本和完整备份完成恢复及发布。
- [ ] 关闭旧服务器和历史附件下载访问后，重复核验所有包内资料和核心流程。
- [ ] 将至少一份经过校验的完整备份下载到本人控制的私有存储，并记录恢复耗时和所需空间。

上传未完成的记录会保留为未完成状态，需要重新上传；浏览器收藏和短期登录会话不属于服务器备份。新服务器的密码、证书和服务账户权限单独配置。

## 源码版本与安全依赖

生产构建应固定 Node.js 24.21.0，并使用 `npm ci` 安装锁文件。当前锁定 `serialize-javascript 7.1.2` 和 `tinypool 2.1.2`；隔离源码检出及附加序列化、双线程兼容性检查已经通过，根目录中旧的安装结果不能代替重新安装后的验证。

2026-10-09 的锁文件审计结果为 52 项：22 moderate、29 high、1 critical。此数量包含依赖传播，不等同于 52 个可以由本站请求触发的独立问题。剩余 `braces 3.0.3` 漏洞尚无已发布修复版本，应持续检查上游并避免将投稿字符串作为 glob 表达式执行。[braces 公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)

剩余 critical 涉及 Vitest UI 服务。生产只运行本站原生 HTTP 服务并提供构建后的静态页面，不对公网开放 Vitest、Vite 或 Docusaurus 开发服务；不能用这一部署范围说明替代后续依赖修复。[Vitest 公告](https://github.com/advisories/GHSA-5xrq-8626-4rwp)

源码包若包含未提交修改，必须明确标记为临时工作区版本，不能把父 commit 当作实际构建源码版本。正式交付前需要确认源码已提交、GitHub 可获取、构建记录与备份 manifest 使用相同的准确版本；临时源码包及试运行不满足这一最终条件。

## 每次正式切换的验收

每次升级或迁移时重新勾选以下清单，并保存日期、源码版本、资料版本和验证方式。下面是可重复使用的验收模板，最终发布及恢复结果另存到维护者的私有验收报告。

- [ ] 最终安全锁文件下，完整生产目录在 Linux 上构建、发布并测量资源占用。
- [ ] 首页、方向、课程、资料详情、历史 ID 和直接刷新均可访问。
- [ ] 固定中文关键词、组合筛选、排序、分页和 URL 参数恢复与基线比对。
- [ ] 所有包内资料可下载，中文文件名、MIME、PDF Range 请求通过。
- [ ] 新收藏功能、取消收藏及收藏筛选通过，不处理原有收藏记录。
- [ ] 新投稿、多文件、外链、新方向及新课程审核发布走通；未审核附件不公开。
- [ ] 构建失败后旧站可用，重试不重复入库，服务重启后任务状态正确。
- [ ] HTTPS、Nginx、systemd 和私有管理员配置在目标环境验收。
- [ ] 已保留回滚所需版本和新收到的投稿，完成一次受控回滚检查。
- [ ] GitHub 当前源码及历史对象清理完成，并通过新 clone 确认不携带真实业务资料。

详细部署、备份、恢复和回滚命令见[运维与迁移](./operations.md)。
