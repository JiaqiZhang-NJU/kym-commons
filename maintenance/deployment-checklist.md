# 部署检查清单

供维护者在源码升级、恢复数据或更换服务器时使用，不发布到网站。每次检查均以实际数据版本、源码 commit 和备份清单为准，不使用固定的历史数量。

## 部署前

- [ ] 记录源码 commit、当前数据版本与 release，保存可回滚版本。
- [ ] 导出完整备份，运行 `backup.mjs verify` 并另存一份到服务器外。
- [ ] 安装 Node.js 24.21.0，使用锁文件执行 `npm ci`。
- [ ] 配置数据目录、发布目录、管理员密码文件、站点来源和路径前缀。
- [ ] 核对磁盘空间、目录权限、文件视图在同卷时的硬链接行为与跨卷时的空间需求。
- [ ] 配置 Nginx、HTTPS 和 systemd；API 只监听本机。

## 数据与构建

- [ ] 数据库完整性检查通过，目录字段、文件路径、大小及 SHA-256 与备份清单一致。
- [ ] 已发布资料、待审投稿、附件和审核状态均保留。
- [ ] 生成目录后，自动化测试、类型检查和完整构建通过。
- [ ] 页面来自 `current/site`，文件来自 `current/files`；源码目录、数据库、密码和私有备份不能公开下载。
- [ ] 在新数据目录恢复完整包，使用清单指定的源码版本独立构建，不依赖其他服务器或未提交的源码。

## 功能与上线

- [ ] 首页、方向、课程、资料页和文件地址可正常访问。
- [ ] 中文检索、筛选、排序、分页、刷新后的 URL 状态与浏览器收藏可用。
- [ ] PDF 预览、Range 下载，以及含中文、空格等名称的文件地址可用；抽样下载并核对内容哈希。
- [ ] 在隔离测试环境验证上传、审核、发布、退回和失败重试，不把测试投稿混入正式资料。
- [ ] 管理员登录和退出可用，HTTPS Cookie 为 Secure、HttpOnly，路径与站点前缀一致。
- [ ] API 来源检查与当前域名一致，未授权访客不能访问审核数据或私有附件。
- [ ] 对外切换后检查 HTTPS、自动续期、API 和备份定时器；记录结果与未通过的项目。
- [ ] 保留旧版本直至验收完成，确认期间收到的新投稿没有丢失。

操作命令与恢复步骤见 [部署与数据维护](./operations.md)。
